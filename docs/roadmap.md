# ポートフォリオMVP公開後のロードマップ

2026-10-26のオーナー方針により、個人開発ポートフォリオの公開条件を以下に限定する。以前のIssue #36 / PR #37 / runbookの追加運用ゲートはこの方針で置き換える。通常の要件、実行権限、branch protection、独立コードレビュー、本番承認は維持する。

## 今回の公開必須

- 初期個人蔵書を固定snapshotに基づくtransactionでadmin限定にする。Book/File/ReadingInfo・既存R2オブジェクトを削除・上書きしない。
- 承認済み非公開領域へ本番DBのcustom-format dumpを作成し、アクセス制限・サイズ・hash・読み取り/形式を検証する。復旧権限と再公開を防ぐ復旧手順を記録する。
- 未認証signupを遮断し、R2の認証後署名GET/CORS・既知の匿名公開経路を確認する。管理API設定を読めない範囲は未確認と記録し、非公開を断定しない。
- 個人蔵書保護後にBetter Auth一般demoアカウントと青空文庫公式由来のEPUB/PDFのみ登録する。
- 公開URLのPC Chromiumで日本語本文、EPUBルビ/目次/章移動/ページ送り/CFI、PDFページ1→2の本文差分、再読込とログアウト/再ログイン後の位置復元を証明する。API 200や画面遷移だけでは合格にしない。
- 匿名401、一般ユーザー管理API403、個人蔵書の一覧/検索/詳細/直URL/ファイル/署名発行/進捗GET/PATCH拒否、admin閲覧を確認する。mobile viewportは表示の基本確認を行う。
- 固定SHA、merge-refのcommit/tree対応、CI、独立レビュー、本番immutable image、実行時刻/browser version、demo書籍ID、手順別PASS/FAILと秘匿済み画面証拠を残す。

P0/P1、個人蔵書漏洩、無認証ファイル取得、重大認可欠陥、既存データ消失リスクは延期不可。本番経路/承認/バックアップ/復旧権限が不足すれば本番変更だけ停止する。

## 延期項目

ここでの優先度は公開後の実施順であり、脆弱性severityとは区別する。

| 優先度 | 項目 | 受け入れ条件 |
| --- | --- | --- |
| 高 | 暗号化オフサイトDB保管・鍵管理 | 承認済み保存先/ACL、管理者所有の認証、鍵保管者と復号手順を確認し、秘密値を公開せず復号を実証 |
| 高 | バックアップ3世代・DB/R2世代同期 | 保存/削除責任者とretentionを決め、3世代の整合manifest・hashを照合 |
| 高 | 隔離復元訓練・独立バックアップ監査 | 非公開の別DB/storageで実backupから復元し、全refs/hashと認可を検証。第三者が証拠を確認 |
| 中 | Cloudflare管理APIの定期設定監査 | read-only権限でr2.dev/custom domain/CORSの期待値との差分を検出し通知。今回読めない設定は未確認として残す |
| 中 | XHTML厳格無害化（既存レビューP3） | 要素/属性/URL allowlist、SVG/object/embed/event/CSS/外部通信の攻撃fixtureを拒否し、日本語・ルビ・出典が保持される |
| 中 | EPUB大容量処理の中断・展開上限（独立レビューP3） | unmount時にdownloadを中断し、圧縮後/展開後サイズと端末メモリの上限を定義して、巨大/高圧縮EPUBでタブ停止を起こさない |
| 中 | マルチブラウザ/モバイル完全E2E | 対象ブラウザと端末を固定し、本文・認可・進捗復元を反復実証 |
| 中 | 監視・自動復旧 | 可用性/認可エラーを秘密値なしで通知し、個人蔵書再公開を起こさない復旧条件を検証 |
| 低 | 影響軽微なP3/UX改善 | 個別Issueに影響・再現・受け入れ条件を記載し、公開必須機能への回帰なし |

XHTML延期は信頼済みの固定公式ソースに限定する。生成前に取得した内容のactive content/外部参照を点検し、実際に危険な内容があれば登録を止めて是正する。redirectは生成コードで追跡を禁止する。未知のソースを許可する根拠にはしない。

## 旧ゲートとの差分

全R2暗号化複製、オフサイト、鍵管理制度、3世代、隔離復元訓練、独立backup監査、Cloudflare定期監査、完全マルチブラウザを今回の公開条件に加えない。DB dumpの読取検証を「復元成功」、既知経路の拒否を「全公開設定監査済み」、ローカルE2Eを「本番E2E」と表現しない。実装上の新しいevidence policyはレビュー済みimmutable imageに含めてから使い、古いruntimeへJSON偽装・ソース差替えを行わない。
